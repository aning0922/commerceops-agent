# 分阶段路线图与外部配置

状态：2026-10-08 首次外部架构审核有条件通过后的修订稿，等待最终确认。以下是计划，不表示已获准开始开发。P0/P1/P2 是产品业务优先级，Phase 0–6 是开发阶段；审核意见中的 P0/P1 则表示整改优先级。

## 1. 交付目标与推荐顺序

**第一交付目标明确为“库存 Agent + 真实飞书审批”。** 采用单 Worker、全局单 Graph 执行并发，以可靠完成一条闭环作为首个可面试版本，不提前追求全部产品能力。

| 里程碑 | 范围 | 验收 | 累计工作量（架构最终通过后） |
|---|---|---|---|
| M1 首个可面试版本 | Phase 1–4：MockCommerce 库存 Agent、真实飞书私聊/群 @ 与显式审批、内部补货项创建/完成/关闭、Base 同步、最小 Web 轨迹与恢复演示 | PRD AC01–07、AC09–11，加 AC08 的干净环境离线复现/真实飞书部分；不宣称 Woo 已接入 | 14–21 工作日 |
| M2 完整 P0 | M1 + Phase 5：Woo 只读测试店、完整 P0 数据对账与备份/交付验证 | AC01–11 全部通过，包括 AC08 的真实 Woo 证据 | 19–28 工作日 |
| M3 完整求职版本 | M2 + Phase 6：P1 日报/定时/追问、受限动态只读 Tool 展示、SOP RAG/文案审核草稿 | M2 验收 + P1 指标、工具选择安全评测、引用和草稿闭环 | 29–43 工作日 |

这里的“完整求职版本”包括 P0+P1，不包括产品 P2 平台扩展或 C-EXT 多 Worker 能力。M1 也必须具备真实飞书证据，不能用纯 Mock 卡片替代。

| 阶段 | 依赖 | 独立交付 | 验收门槛 | 粗略工作量 |
|---|---|---|---|---|
| Phase 0 调研设计与审核修订 | 当前文档修订授权 | 十份核心设计、调研证据、AGENTS/README、审核修订 PR | 外部有条件通过；修订后等用户最终确认 | 已完成初稿，本轮修订 |
| Phase 1 工程底座与技术探针 | 最终架构确认；Docker；外部配置用于真测 | 基础 CI/敏感扫描先行，uv/Node 锁、PG migration、单 Worker/单 Graph 槽、checkpoint crash probe、飞书回调/Base probe | G1 Docker、G2 LangGraph Checkpoint、G3 飞书真实回调；缺证据记阻塞，不算通过 | 3–5 工作日 |
| Phase 2 确定性库存垂直切片 | Phase 1 本地底座 | Mock fixtures、统一契约、快照、规则、API 报告、模型受限说明 | 金标完全一致；空/异常/分页失败不产生错误执行计划 | 3–4 工作日 |
| Phase 3 审批与恢复闭环 | Phase 2；G2 图恢复结论 | 显式在途假设确认、approval、interrupt/resume、内部补货创建/完成/关闭、outbox、最小 Web | 拒绝/重复、HTTP 审批冲突、单 Worker 重启、提交后崩溃；关闭后新周期 | 5–7 工作日 |
| Phase 4 飞书闭环与 M1 交付 | Phase 3；G3 真实回调；测试组织 | 飞书正式卡片/Base（2–3 日）+ Compose 离线复现、轨迹/故障演示与录屏（1–2 日） | M1 指定 AC；能解释数据、审批、恢复；不含 Woo | 3–5 工作日 |

工期按一位主要执行者估算：M1 为 3–5 + 3–4 + 5–7 + 3–5 = 14–21 日；加 Phase 5 后 M2 为 19–28 日；再加 Phase 6 后 M3 为 29–43 日。按每周 5 个有效工作日，M3 约为 6–9 个工作周，另加账号审核、网络问题和用户评审等待。**不承诺全部功能在 4–5 周内完成。** 新增最小关闭操作与基础 CI 纳入上述阶段估算；动态只读展示纳入 Phase 6，不挤入 M1。Phase 1 结束后根据探针结果重估，不把范围表当固定工期保证。

### 1.1 三个早期验证闸门

与 RESEARCH 的 G1–G3 使用同一编号；本轮状态都仍是未执行，不因文档修订而变更。

| 闸门 | 执行时点与必须证据 | 不通过时的边界 |
|---|---|---|
| G1 Docker / 本地环境 | Phase 1 起始：Docker daemon、Compose/PG 健康、持久卷重启、业务迁移/checkpointer setup 可复现，记录版本与命令 | 可做文档/离线纯函数；不能宣称持久层或容器运行通过 |
| G2 LangGraph Checkpoint | G1 后尽早：单 Worker 单执行槽、真实 PG interrupt、旧进程终止后同 thread 恢复、业务提交后 checkpoint 前 kill 的幂等回执 | 阻断 Phase 3 恢复验收；不以多 Worker/fencing 研究拖延基本闭环 |
| G3 飞书真实回调 | Phase 1 尽早：真实私聊/群 @、新版 card.action.trigger 长连接；显式确认/拒绝 action 与对象确认键往返，记录 operator/event_id/响应延迟；附 Base 最小读写探针 | 无凭证记 blocked_external；可继续本地 Phase 2/受控 Phase 3，不得交付 M1 或称真实审批通过 |

G3 探针只证明接入能力，正式 T3 事务、拒绝/重复确认与 AC10 由 Phase 3/4 完整验证。基础 CI 在 Phase 1 首批提交建立，不需要真实平台密钥；G3 不能由 CI 替身冒充。

### 1.2 后续并发扩展 C-EXT（不阻塞交付）

M1/M2 继续单 Worker、全局单 Graph，M3 默认沿用；API 审批并发仍需 CAS/唯一约束。只有实际吞吐瓶颈且用户另行确认后，才评审多个 Graph 执行槽/多 Worker、per-thread 锁、fencing 和失联接管，并执行 TEST_PLAN R02–R04。C-EXT 无承诺日期、不计入 M1/M2/M3 估算；不能从通过单实例恢复推导出支持多 Worker。

## 2. 每阶段验收证据

- Phase 1：基础 CI 成功运行及敏感扫描阻断样例；版本锁/环境说明；G1–G3 各自证据。未具备凭证明确 pending，不能把 skipped 计通过。
- Phase 2：fixture manifest、黄金计算结果、已知异常列表、一次真实模型说明及一次受控失败降级。
- Phase 3：R01/R05–R12/R17、S01–S03 的数据库断言与轨迹；A01–A08 假设确认、C01–C05 完成/关闭；Web 刷新不丢任务。R02–R04 不属于本阶段闸门。
- Phase 4 / M1：真实飞书私聊/群 @ 录屏或截图；显式确认/拒绝/重复；Base 行回读；干净 Compose 离线启动与关键失败恢复演示。无 Woo 证据时如实标注尚未接入。
- Phase 5 / M2：Woo 后台/API 数量金额对账；备份还原后待审批任务继续；完整 AC01–11；不存在密钥和旧项目运行路径依赖。
- Phase 6 / M3：P1 日报/调度/文案验收与 D01–D05 动态只读评测，保留模型版本/成本和实际工具序列。

用户需要在阶段评审决定继续。GitHub 仓库、推送及 PR 已按后续协作要求授权，遵循 [AGENTS.md](../AGENTS.md)；合并 main 仍须用户确认。云部署与扩大平台权限另需用户授权，不因本地功能可用就自动发布。

## 4. 风险与处理顺序

| 优先级 | 风险 | 缓解 / 验收阻断 |
|---|---|---|
| 高 | 审批状态、图进度、外部副作用不存在天然统一事务 | 业务唯一键+短事务+outbox+恢复协调；关键 crash tests 是门槛 |
| 高 | 飞书测试组织权限/长连接新版卡片实际投递未知 | Phase 1 真机探针；必要时受鉴权 HTTP 回调，不能静默跳过卡片验收 |
| 高 | Woo 数据语义/共享库存/退款与模拟数据不同 | 契约测试、实际样本对账、质量闸门；只读测试店 |
| 中 | PG 队列过早追求并发，变成通用框架 | 单 Worker 单 Graph；保留幂等/恢复；多 Worker 与 R02–R04 单列 C-EXT |
| 中 | 模型编造数字或“已执行” | 程序渲染数值、结构化引用、业务状态模板、工具写权限隔离 |
| 中 | 外部幂等键保留期限不足 | PG 长期回执、外部稳定业务 ID 对账、unknown 人工处理 |
| 中 | 本机 Node 20 生命周期、版本快速变化、Docker 未启动 | 项目容器 Node 24 LTS；版本兼容 probe；不改全局环境 |
| 中 | 前端/RAG 挤占可靠性工作 | Web 极简；RAG/pgvector 放 P1；无报表大屏需求 |
| 中 | 本地电脑休眠影响接收/定时 | 明确在线窗口；持久 job 补偿；有全天需求时另评部署 |

## 5. 架构评审需确认的取舍

本轮落实的推荐：M1 优先库存 Agent+飞书审批；内部补货项支持创建/完成/关闭，不改真实库存；单 Worker/单 Graph；在途未知使用版本绑定的联合确认动作；基础 CI 在 Phase 1 开始加入；动态只读 Tool 展示安排 Phase 6。Woo 只读、pgvector/RAG 延至 P1、一名有效审批决定、变更重批及 20 条审批上限保持。

最终确认事项：M1/M2/M3 的范围和估算；是否接受未知在途按 0 估算的专用批准动作（若不接受，该类计划全部阻止执行）；真实 L/R/S、在途来源、是否要求职责分离；完成/关闭是否沿用同店铺 approver 权限；模型服务与预算。文档默认值足以说明方案，本轮不因此开始实现。实际采购/库存写入仍属于新的重大范围与权限评审。

**本轮仅在 review/phase0-fixes 修订文档并提交 PR。等待最终确认，不开始 Phase 1，不创建 CI workflow 或业务代码，不合并 main。**
