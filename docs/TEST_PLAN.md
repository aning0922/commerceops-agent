# 测试与场景评测计划

状态：Phase 0 测试设计，**以下用例尚未实现或运行**。本轮只校验文档和仓库范围；没有业务测试通过结论。

## 1. 证据分层

| 层级 | 工具与对象 | 证明什么 / 不证明什么 |
|---|---|---|
| 单元 | pytest、纯规则、固定 clock、模型替身 | 计算/校验确定性；不证明外部可用 |
| 契约 | Pydantic、MockCommerce、脱敏 Woo/飞书响应 | 字段映射、异常分类；不证明真实授权 |
| 集成 | 真实 PostgreSQL、实际 checkpointer、双 Worker | 事务/锁/唯一约束/恢复；不能用 SQLite 替代 |
| API/Web E2E | API+Worker+PG+Next，Playwright | 登录、提交、刷新恢复、审批与状态展示 |
| 真实飞书 E2E | 测试组织、桌面/移动客户端 | 私聊/群 @、新版卡片长连接、实际权限与 Base |
| 真实 Woo 合同 | 只读测试店 key、已知测试订单 | 真实 API 认证/分页/字段语义 |
| 模型评测 | 版本化样本+固定事实+真实 provider | 意图与报告质量、耗时成本；不用于代替业务安全测试 |

每份结果必须写 source_mode、model_mode、approval_mode、依赖版本、数据集版本、执行命令和时间。模拟审批标为 simulated；真实点击才算 human_feishu/human_web。

## 2. 确定性单元测试

- 库存风险：正/零/负/null 库存；正/零销量；风险线等值；ceil 取整；在途 0/未知/已确认；已有开放补货；共享父库存隔离；数量上限。
- 示例金标：70 件/7 日、库存 20、在途 0、L=3/R=7/S=2，得到 D=10、T=120、Q=100、覆盖 2 日、风险。
- 数值与时间：Decimal `0.1+0.2` 不产生 float 误差；混币拒绝合并；bool/NaN/小数件数拒绝；窗口起点包含、终点排除、跨 UTC 日界、DST 测试时区。
- 订单与退款：processing/completed/refunded 证据、未知状态、跨期退款、无数量退款、取消不回溯篡改旧快照、退款不等于回库。
- 权限：operator 不能批准，admin 不隐含 approver，停用账号/角色撤销，跨组织/店铺、伪造 card value、过期/非当前 plan。
- 状态：所有非法转换拒绝；同一 key 不同 payload 报冲突；hash 的排序/Decimal/null 规范化稳定。

只测业务合同与失败不变量，不为普通 getter/文档改动堆实现镜像测试。

## 3. 并发与故障注入矩阵

| ID | 注入点 | 必须断言 |
|---|---|---|
| R01 | inbox 事务提交后、ACK 前 kill Gateway | 重投仍一个 task 和首个 job |
| R02 | 两 Worker 同时领取同一 ready job | 一位持有效 lease；同 task 图独占 |
| R03 | lease 过期但旧 worker 仍持 graph 锁 | 新 worker 不同时执行；旧 epoch 无权提交业务 |
| R04 | 旧锁连接断开但旧进程仍在跑 | 取消旧调用；不确认其停止则 needs_attention，禁止 checkpoint 双写 |
| R05 | plan/outbox 提交后、中断 checkpoint 前 kill | 重放不新建计划/卡片意图；卡片发送在 ready 后 |
| R06 | checkpoint 中断后、ready_at 写入前 kill | 协调器补 ready，审批可恢复 |
| R07 | 审批决定到达时 Worker 尚未观察中断 | 决定持久存在，resume job 延期后只消费一次 |
| R08 | 两用户并发同意/拒绝、同意重复 10 次 | 只有一个决定生效；冲突返回既有决定 |
| R09 | 批准后角色撤销/计划过期/库存实质变化 | 不创建补货，新版本重新审批或明确终态 |
| R10 | 补货事务中途 kill / rollback | 所有计划项全无，不能部分执行 |
| R11 | 补货事务提交后、checkpoint 前 kill | 重放返回同一 execution，每 SKU 一条 |
| R12 | 不同 task 同时批准同 SKU | active stock_pool 唯一约束阻止第二份安排 |
| R13 | 外部创建成功但响应丢失 | outbox unknown；原幂等键/对账，不产生无限重复行 |
| R14 | Bitable 429/5xx/业务 code 非 0/写冲突 | 同表串行，有限延期，内部成功状态保留 |
| R15 | 消息 unknown 超过 1 小时去重窗口 | 不声称安全重发；进入对账或人工处理 |
| R16 | 旧 outbox 晚于新投影到达 | 旧版本不能回写为旧审批/业务状态 |
| R17 | Worker/API 重启、任务正待审批 | 无内存依赖；可继续原 thread 和原计划 |
| R18 | 部署新的图节点顺序，旧任务等待中 | 继续旧版本或阻止恢复，不能错配 interrupt |
| R19 | DB 暂停、模型卡住、订单某页失败 | 入站不假 ACK；无长事务；数据不完整不执行 |

关键测试使用可控 barrier、事务钩子和进程终止，不依赖随机 sleep 猜竞态。R01/R05/R11/R13 是演示和面试必须能解释的四个崩溃窗口。

## 4. 飞书与 Web 端到端

飞书手工检查：已发布应用、当前客户端版本、私聊和群 @、未 @ 不触发、非授权人点击、重复点击、拒绝、过期、重启继续、表格读回。记录 task_id 与脱敏截图。Playwright 只覆盖 Web 页面与受控集成，不能替代飞书原生客户端真机验收。

Web 自动化：授权用户登录；提交自然语言；显示任务编号；刷新后仍有报告/审批；不同身份权限一致；CSRF/跨源请求受限；批准后执行/同步状态分开；重复按钮不会新建任务；不存在无认证 localhost 特权后门。

外部配置不具备时 CI 标记真实飞书/Woo测试 skipped 并说明原因；不能把跳过计为通过。至少一次固定真实模型成功调用、一次飞书完整闭环与一次 Woo 真实只读查询才算集成阶段完成。

## 5. Agent 评测

初始冻结 40 个用例：12 个库存请求改写、6 个参数澄清、6 个状态/证据追问、6 个越权/提示注入、5 个缺失或矛盾数据、5 个不支持场景。固定 facts、expected intent、允许 tools、必需引用及 forbidden actions。

| 指标 | 初始验收目标 |
|---|---|
| 路由与参数正确率 | ≥95%，同时逐例检查错误原因 |
| 必须澄清的模糊请求 | 100% 不触发写操作 |
| 结构化事实表数值 | 100% 与金标一致 |
| 越权/注入/虚构成功 | 固定安全用例中 0 次未授权执行、0 次虚构执行完成 |
| 引用有效性 | 100% SKU/报告引用可追溯；无证据时明确说明 |
| 报告可读性 | 用户按准确、清楚、可操作三项抽审；每项 1–5 分，均值≥4 |
| 成本与时延 | 每任务可查询 usage/latency；未知 cost 为 null；预算超限会停止 |

固定安全集通过并不证明对所有攻击安全；授权必须由代码确保。真实模型评测至少重复 3 轮记录波动，调整 prompt 后保留独立 holdout；禁止把测试结果调到金标字符串就宣布泛化成功。

## 6. 可复现与交付闸门

Phase 1 锁 Python/Node/镜像和 checkpointer 依赖，验证迁移一次与重复执行；Phase 2 验证 fixture 金标；Phase 3 验证恢复矩阵；Phase 4 加真实集成证据；Phase 5 才要求 Compose 干净启动、完整测试、备份恢复演练和演示脚本。

验收基线机器配置与数据量须记录。入站 p95<1 秒目标用 100 次受控事件测量；恢复扫描≤30 秒，受控离线分析 p95<10 秒。真实接口统计单独列出，不把模型网络抖动混作本地队列吞吐。禁止用覆盖率百分比替代关键不变量验收。
