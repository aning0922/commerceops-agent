## 2. 日报详情：口径先于解释

页面从上到下依次为报告标题/日期、来源和完整性提示、指标卡、异常列表、口径与证据、定时/投递摘要、追问入口。报告完成和推送状态分开；示例文案为“日报已生成 · 推送结果待核实”，禁止合并为“日报已送达”。

| 事实 | 展示要求 | 后端必须冻结的口径 |
|---|---|---|
| 统计窗口 | 同时列店铺 IANA 时区、起止本地时间及“结束不含”；详情保留 UTC 起止 | 日报属于哪个业务日期、完整自然日还是其他窗口、边界是否 `[start,end)`；不按浏览器当前日期计算“昨日” |
| 币种与金额 | 金额旁明确币种；按服务端精度格式化，不用 JS 浮点求和或换算 | 单币种或分币种结构、精确金额类型/精度、折扣/税费/运费是否计入；混币种不能给一个合计 |
| 订单/支付/退款 | 名称、值、单位、可展开口径；有证据链接 | 下单、支付、退款各自时间字段与状态过滤，退款按发生日还是订单 cohort 归属、撤销/部分退款处理；不能将毛收入标成利润 |
| 比率与比较 | 展示服务端计算值与比较窗口；不可比较显示原因 | 分母、分母为零的 null/不可计算语义、前期完整性与币种一致性；UI 不补 `0%` 或无限增长 |
| `as_of` 与采集 | 标“数据观测截至”，另外列生成时间和本次读取时间 | 观测/采集起止、快照时间语义；多来源各列 `as_of`，不拼称同一原子快照或“实时” |
| 完整性 | 完整空数据、部分缺失、采集失败和未知分别显示 | cohort/分页完整性、质量标志、缺失范围和可用指标；字段缺失不是零，旧报告不能冒充本期 |
| 异常 | 显示规则名、严重度文字、实际值/阈值/比较口径、规则版本及引用 | 确定性规则及金标；无异常须基于完整且成功运行的规则，缺数据不能显示“一切正常” |

指标范围由后端先冻结，不在本稿确定指标公式或新增业务阈值。UI 只渲染程序产生的事实；模型回答不能覆盖卡片数值、异常级别或统计窗口。金额缺失显示“未报告”，数量未知显示“未知”，服务端确认的完整空集合才显示 0。缺少时区、币种或绑定字段时采用安全错误/不可展示状态，不猜人民币、台币或本机时区。

证据入口要能从每个指标/异常定位到本报告的事实依据。优先同页锚点和受鉴权的内部详情，链接文本包含指标名与证据用途。报告来源区显示脱敏来源标签、report/snapshot 标识、规则版本、观测时间、完整性与事实 hash；技术标识可放 details。禁止显示订单客户个人信息、原始响应或凭据。

深链只用合同允许的内部资源类型及标识构造；不直接将模型文字或来源商品描述变成任意 URL。打开证据时重新鉴权；无权/不存在使用统一安全提示，不泄露标题、金额、SKU 或原始订单内容。带 fragment 的链接也不授予读取权限。历史报告保持原窗口、快照与规则版本，不能静默跳到最新事实。

## 3. 生成、调度与投递分别展示

以下是 UI 所需语义，不是新的后端枚举；真实 enum 到文案的映射以冻结合同为准。未知 enum 不落到绿色“成功”，拒绝不合法响应或显示安全的未识别状态。

| 维度/语义 | 页面文案及下一步 | 不能据此推断 |
|---|---|---|
| 本期尚无报告 | “本期尚未生成”；有权时查看计划记录 | 不是完整空日报，也不自动创建 |
| 排队/运行中 | “等待生成/正在生成”，显示服务端时间；只读刷新 | 无进度百分比，不承诺固定完成时间 |
| 完整/部分/失败 | 分别显示指标和缺失说明；失败时显示安全原因与 trace_id | 部分数据不标完整，读取失败不覆盖报告的业务状态 |
| 计划启用/暂停/不可用 | 规则摘要、时区、计划版本、下次 due_at 或明确未报告 | “启用”不等于 Worker 在线或发送器有资格 |
| 迟到/恢复补最近一期 | 原 due_at、实际受理/生成时间、服务端补偿原因及被跳过期数（若提供） | 不根据浏览器时钟自行补报，不展开补全部历史 |
| 重复 schedule/due_at | “本期已受理/已有日报”，指向同一有权记录 | 不新增第二张日报，不把去重计为新生成 |
| 投递未配置/禁用/无资格 | 明确原因，保留日报可读状态 | 无发送资格不等于生成失败 |
| 投递等待/受理/核实成功 | 目标安全别名、尝试次数、最后事实时间与验证模式 | 平台受理不等于客户端已读；Fake 不等于真实平台 |
| 投递失败/结果未知 | 分别显示“发送失败/发送结果待核实”；只读刷新原记录 | 不换键重发，不把 unknown 改作失败或成功 |

调度详情以服务端 `schedule_id + due_at` 对应的运行记录为依据，窗口和 due_at 不混用；同一报告有多条投递时分别列状态。详情页不显示接收对象原始 ID、令牌或发送凭据，目标别名也仅在当前身份有权时展示。来源 Mock/Woo 测试店、解释 offline stub/实际 provider、投递 Fake/受控平台三个维度分别标注。

没有冻结重试语义前不提供自动 POST 重试、手动“再推一次”、启停调度或恢复按钮。显式刷新只 GET 读已有结果，延迟响应不得将旧报告/旧权限内容写回新页面。

## 4. 证据追问交互与失效

从日报详情进入，抽屉标题为“追问此日报”，常驻显示当前业务日期、店铺安全名称、report/snapshot 绑定和窗口。问题草稿只存当前页面内存；切换报告、切换身份、登出或撤权即清除。不复用上一份报告的回答或群里其他人的上下文。

1. 用户输入问题；提供“这项异常依据是什么”等不含虚构指标的文字建议。点击建议只填草稿，不提交。输入长度、支持问题类型和多轮上限由合同定义。
2. 明确点击“提交追问”才受理。若合同采用持久提交，UI 固定原请求键及 payload，等待时禁重复；超时只按原回执读取，不能自动换键再发。若采用同步只读协议，则依冻结合同处理，不能先假定 GET 会调用模型或 POST 只是读缓存。
3. 回答区域将程序事实/证据引用与模型叙述分开。只接受本报告绑定的引用，逐条可定位；金额、比率或异常若没有本报告事实支持，不能渲染成权威指标。显示证据模式、模型/规则版本与可用的 usage/耗时，未知为“未报告”。
4. 点击引用打开证据区，保留返回位置；跨报告比较或“查现在库存”先说明本入口仅限本报告。动态只读工具是后续切片，本入口不隐式重新采集或扩大店铺/日期范围。

| 状态/失败 | 展示与交互 |
|---|---|
| 无现成解释 | “尚无已有解释”；不以模板伪造模型回答，也不把查看动作自动变成模型调用 |
| 证据不足/问题有歧义 | 展示缺少什么及服务端澄清提示；保留原问题，不编造原因、数字或引用 |
| 不支持/越权/要求写操作 | 固定安全原因；不发起审批、补货、订单修改或推送 |
| 模型失败/预算停止 | 明确回答未完成或已停止；日报事实继续独立可读；只有服务端实际返回且标明的降级结果才展示 |
| 响应引用错绑/缺字段 | “暂时无法安全展示回答”；不回退成上一次回答或 UI 生成的替代解释 |
| 追问提交结果未知 | 显示原请求待核实、允许读原回执；关闭抽屉不代表服务端取消 |
| 登录失效/权限撤销 | 清报告、来源、回答、输入、抽屉与准备请求，进入现有安全壳；迟到响应无效 |

现有 `LiveReport` 的“本报告已有解释”仍按旧合同只读缓存；不改名后直接接成追问。新追问组件必须等待独立 DTO、请求/回执及资源绑定合同。

## 5. 权限与响应绑定

沿用 operator/approver/admin 的既有最小权限原则，M3 的日报读取和追问资格须由后端明确：operator 的本人任务范围不能直接扩大成全店日报读取；approver 的审批资格不能自动推导日报资格；admin-only 不取得业务读取权。后端需声明日报所属对象/受众与角色各自店铺 scope、接收人资格、配置 owner 的关系，兼任仍逐动作在同一角色 scope 内判断，不拼接权限。

导航能力、列表计数/分页游标、报告详情、证据、调度、投递、追问回执全部用当前服务端权限过滤。计数不能泄露无权报告或其他人的计划。UI 不传 actor/role 当授权；新能力字段缺失时不自行从旧 `can_read_tasks` 推导授权。

响应必须核对当前身份生命周期及请求对象，再核 report/snapshot/facts_hash、必要版本与 evidence refs；同一抽屉关闭、路由切换、重新读取、身份失效时递增请求世代或取消请求，忽略旧响应。401/403 保持现有全局清理行为，不静默重新登录；无权与不存在详情统一安全提示。业务空列表、服务不可用、schema 不匹配和会话失效是独立状态。

## 6. 后端 DTO 与路由需求清单

下表给出所需操作和建议 API 资源形状，用于后端合同讨论；这些 API 当前未声明存在，不写客户端、不创建假响应。最终路径、HTTP 方法、schema_version、状态码与 enum 由 Backend 冻结并经 Root 转交。若采用现有 task/report 资源，保留同样语义即可，不要求另建表或第二套状态机。

| 操作/候选资源 | 最小响应或输入语义 | 合同需解决的依赖 |
|---|---|---|
| 会话/能力：沿用会话入口，扩展方式待定 | 当前身份下日报读/追问/调度读的能力和对象约束 | M3 角色 scope/日报受众；与旧 schema 严格校验兼容的版本策略 |
| 日报列表：候选 `GET /api/v1/reports/daily` | 授权条目、稳定 report_id、业务日期/窗口、店铺/来源、生成/质量摘要、分页 | 筛选、排序、cursor、计数同权限；空列表与未配置区分 |
| 日报详情：候选 `GET /api/v1/reports/daily/{report_id}` | 不可变绑定、精确指标/币种、窗口/时区、各 as_of、完整性、异常/规则版本、证据引用 | 报告/快照/hash 一致性、null 语义、金额类型、异常阈值、历史版本读取 |
| 证据读取：候选详情内嵌 refs 或 `GET .../{report_id}/evidence/{evidence_id}` | 受控证据类型/标识、可展示的脱敏事实、来源和定位信息 | ref 必须属于报告且当前有权；支持的内部深链集合，不返回任意可执行 URL |
| 调度/运行读取：候选 `GET /api/v1/report-schedules/{schedule_id}` 及关联 runs | 配置版本、时区、周期/状态、next_due_at；各 due_at、运行/补偿/重复原因及报告关联 | 单 Worker、补最近一期和停机语义；无下次时间的原因；不要求 Web 配置写 API |
| 投递读取：候选日报详情内嵌或 `GET .../{report_id}/deliveries` | 授权目标别名、逻辑投递标识、状态/attempts、事实时间、安全错误、验证模式/资格 | 平台受理与核实等级、unknown、重复/重试与当前目标版本；不泄露凭据 |
| 追问受理：候选 `POST .../{report_id}/inquiries` | report/snapshot/hash 绑定、问题及合同指定上下文标识；如为持久操作则有 request_key/回执 | 是否模型调用、CSRF、幂等/冲突、输入/预算上限、异步/同步及当前权限 |
| 追问结果/原回执读取：候选 `GET .../{report_id}/inquiries/{inquiry_id}` 或统一 request 资源 | 明确状态、绑定、答案/claims、有效 refs、澄清/不足/停止原因、安全模型与 usage 元数据 | 请求结果未知如何只读核实；多轮隔离、迟到/撤权、回答绑定校验与脱敏 |

所有响应需有可验证协议版本、trace_id、server_time、安全错误分类；精确结构以合同为准。服务端确定性金额/统计/权限/去重仍由 Backend 负责，Web 不以 checkpoint、按钮禁用或本地缓存替代持久保证。

## 7. 窄屏与键盘方案

保持现有 `1280 / 1000 / 700px` 断点和 1440/1280/390 宽度验收；桌面沿用 224px 侧栏、72px 顶栏、600px 抽屉、现有字体/色板/间距及 44px 最小按钮。700px 以下沿用顶部可换行导航、单列指标卡、16px 页面/卡片内边距，抽屉宽不超过 viewport。200% 缩放按重排验证，不以等效截图替代实际缩放。

指标、异常和调度行在窄屏按带标签的纵向组显示，保持名称→值/单位→窗口→完整性→证据的阅读顺序；长币种说明、规则名、目标别名和标识可换行。必要的明细表可在有可访问名称的区域内横向滚动，页面本身不横向溢出；不能靠省略号或只显示 Top-N 隐藏异常依据。状态同时有文字和颜色，不以绿色表示未知。
