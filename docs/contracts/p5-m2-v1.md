## 1. 来源与配置绑定

A 复用原 `InventoryRunner/InventoryStore`、`ApprovalRunner/ExecutionStore` 和当前 session/role/shop 权限。
Woo 来源标识固定为 `woocommerce_test`，仅新的本地合成测试店；Mock 的原参数、原任务和回执保持可读。
`business.shops` 的组织/店铺 UUID、`adapter_kind`、`external_shop_key`、币种、时区和 `config_ref`
必须与服务端显式私有配置逐项匹配；Woo 仅 `environment=test`，不得按客户端声明授予资格。

服务端配置以当前店铺 `config_ref` 查找唯一不可变版本，包含组织/店铺、外部店铺键、
`source_config_version`、固定测试业务时钟、HTTPS 原点、只读 key/secret/CA 文件引用及采集限额。
配置/秘密文件沿用当前用户、0700/0600、非 symlink、有界 FD 读取；不自动读 `.env` 或旧运行目录。
版本是服务端维护的非秘密标识，不是密码/凭据散列；公开 DTO 不含 URL、文件路径、key 或 secret。
任务持久化服务端绑定后的来源版本与参数；执行前再次核当前配置与店铺资格，缺版本或不符即拒绝/待处理，
不将旧任务偷偷改绑最新版本。配置轮换不会改写旧 snapshot、plan hash、nonce 或 request key。

`(organization_id,shop_id,config_ref,source_config_version)` 必须登记到 DB 或可信只读注册表中的
不可变记录，并绑定规范编码后的非秘密配置 digest。digest 覆盖 HTTPS origin、external_shop_key、
adapter/environment、currency/timezone、profile/D、全部采集限额和不可变 key/CA 引用。
API 创建、N01、初次采集、T4 各自解析实际配置并与已登记 digest 比较；不能只比较版本字符串，
也不能在运行时把刚计算的新 hash 自动登记为正确值。同 version 内容改变必须失败关闭。
task/snapshot/observation 引用同一登记绑定，0018 同时检查来源与该不可变绑定的谱系。
同一 key/CA 引用下文件字节改变时，私有 pin 必须拒绝；合法轮换须新不可变引用/版本并重新登记。
秘密及秘密文件的 hash 仅保留在受保护的私有 pin 中，不进入公开 DTO、日志或 DB；
公开配置 digest 只覆盖非秘密引用和配置值，不包含秘密本身或其 hash。
登记 digest 是 server-only 不可变绑定；客户端仍只传版本，runtime 与请求处理均无自行登记/更新权。
N01 只核非秘密配置与登记记录，不为预解析读取 secret；实际 factory 使用 key/CA 时才核私有 pin。
准备/轮换属于显式私有配置交付，不增加配置治理平台。

本地业务 API/Worker 可使用同机进程访问原 loopback/TLS Woo，不放宽 transport 的目标限制。
必要 PG 连接仅使用本批新 owned overlay 的显式 `127.0.0.1` 临时映射，登记端口/截止并独立核关闭；
根 Compose 默认无 PG 宿主发布保持。不得改为任意 DNS/外网目标或复用旧数据库。

## 2. 给 B 的创建与 capability 合同

现有 `GET /api/v1/config?shop_id=UUID` 增加可选 `config.commerce_source` 对象：

```json
{
  "schema_version": "p5-commerce-source-v1",
  "source_kind": "woocommerce_test",
  "source_config_version": "server-owned-version",
  "creation_enabled": true
}
```

只有当前有权 session/组织/店铺、有效服务端绑定和已启用来源才可返回 `creation_enabled=true`。
它仅说明可以提出请求，不代表报告完整或可以批准执行；写入口仍逐次重新授权。
Mock 可返回同形对象，版本为 null。已知 Woo 店铺的绑定缺失、无效或 digest 不符时，
必须返回明确的 `commerce_source` 且 `source_kind=woocommerce_test/creation_enabled=false`，
或安全错误；不得省略该对象诱使 B 回退 Mock。缺省兼容仅适用于服务端已确认的 Mock 店铺或
明确的旧 Mock 兼容响应；来源未知时不得猜测 Mock 或开放创建。
每店铺配置投影中的 `source_mode` 如用于来源展示，必须取当前店铺实际 adapter，不再硬填 mock；
来源展示最终以当前任务/报告冻结 provenance 为准，不能以全局配置覆盖历史报告。

现有 `POST /api/v1/tasks` 保留 `schema_version=p3-web-v1`、`mode=new_cycle`、request_key、shop_id。
其 `parameters` 新增严格的 Woo 分支，按 `source_mode` 区分；Mock 分支原字段不变：

```json
{
  "source_mode": "woocommerce_test",
  "source_config_version": "server-owned-version",
  "L": 3,
  "R": 7,
  "S": 2
}
```

Woo 分支不接受 `fixture_case/dataset_version`、now/window、URL、key、角色、计划或建议数量。
来源版本来自 capability，服务端与当前私有绑定复核后才持久化；旧版本拒绝，不自动重发或换键。
L/R/S 沿用显式确认与0–365边界，示例值仍只是演示参数，不是用户真实业务配置。
`mode=from_report` 的既有五个来源引用字段不变；从原已封存来源恢复参数与版本，不额外创建来源分析。
原 T1 原子任务对、不可变来源、十次重放幂等、UNKNOWN 原字节/原键核对规则保持。
只有 A 发布并获审的 schema/能力实现后，B 才接 Woo 创建；单有来源文案不开放按钮。

## 8. 飞书同源入口与截止P2整改候选（2026-10-26）

3af 的 public DTO 已经原 Reviewer 核定可释放 B；后端因截止 P2 保持 HOLD。
原同步 psycopg 调用不能由外层 asyncio timeout 约束，statement_timeout 也不能限制客户端收包；
原凭据读取在 fstat 之前以阻塞方式打开 FIFO。此前作者通过记录保留，不代签这两个反例。

后续候选将 Woo factory 改为可等待的异步解析，原 Mock factory 不变。唯一18秒绝对截止覆盖
async connect、第一条配置查询、source SELECT/fetch、私有配置与原HTTP逐I/O；调用者只能缩短它。
使用新建 autocommit 只读连接，不执行额外COMMIT/ROLLBACK。到期/外部取消先本地关闭已取得的连接，
再取消并回收解析任务，不在线程里遗留同步数据库操作；服务端statement_timeout仅为辅助。
Woo key/secret/CA以O_NONBLOCK打开，在同一FD验证regular/owner/0600与长度，pin与TLS/auth
继续使用同一次读取字节。DB凭据也复用已有非阻塞私有FD读取。

飞书正式T1/F02复用原Gateway/inbox/身份/权限/请求键/T1事务，不增加文法、状态机或SDK方法。
显式Woo Gateway参数按同一source_config_version解析服务端登记；F02候选冻结该版本、D窗口和
全店scope，initial/明确确认/发送准入时复核source digest；supplement仅核权限和冻结候选。
