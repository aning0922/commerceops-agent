## 用户逐项验收

1. [ ] **欢迎与路由：** 打开 `/v4`，确认显示合成演示说明和明确的进入操作；从页面导航进入 `/v4/demo` 与 `/v4/settings/demo`，确认导航状态和页面内容符合预期。三条路径是辅助/受限入口，六张规划卡片显示尚未开放。
2. [ ] **身份与两店：** 创建演示空间，确认显示当前视角、有效期和授权店铺；逐一切换两店，确认摘要随店铺变化，界面没有把其他店的数据留在当前选择下。R3 对 operator 的两店响应与摘要绑定有实际验证。
3. [ ] **角色：** 切换至审批人和受限管理员，再切回运营；确认授权店铺数与界面内容相符，受限管理员无授权店铺时不显示其他店摘要。R3 验证了角色切换及重新读取的服务端上下文；人为视觉和理解程度仍待确认。
4. [ ] **重置：** 打开确认框，先取消并确认未误操作；再次确认重置后检查明确反馈、当前身份和可见数据状态。R3 覆盖确认及服务端版本推进；不同访客空间不受影响的完整性须结合相应 PG/API 回执，不单凭视觉判断。
5. [ ] **退出与再进入：** 退出后确认当前身份与摘要清除；刷新或重新访问时确认需要明确重新进入，不把旧页面缓存当有效身份。R3 核验退出反馈和当前浏览器 cookie 清除；其他浏览器/设备不在该次证明范围。
6. [ ] **移动与键盘：** 以窄屏查看已登录页面，使用键盘进入设置、打开重置框，Tab 在框内移动，Escape 关闭并返回触发按钮；检查文字、按钮及导航可见、无横向滚动。R3 对 390px 及以上列动作有实际覆盖，但不代替用户设备和完整无障碍审计。
7. [ ] **200% 和动态效果：** 在浏览器原生缩放 200% 下检查欢迎、已登录内容、设置及重置框，滚动查看全部区域；重点检查文字、按钮、焦点和不遮挡。R3 已以真实浏览器缩放和五段覆盖取证，视觉可读性仍需人工确认；reduced-motion 的实际媒体状态已在该用例检查。
8. [ ] **断网及恢复：** 在可控本地测试窗口断开连接，观察状态提示、过期/未知操作和恢复方式；恢复网络后先核对原操作，不应凭空显示成功或在未知状态自动重复业务提交。该项的完整真实断网浏览器链仍待单独执行，不能用 fixture 假定通过。
9. [ ] **边界说明：** 页面未连接真实店铺、未调用真实模型、未对外发送；规划项不应呈现为可执行业务。检查文案是否清晰、用户能否辨认演示状态及未开放项。
